- **Migrated read-only properties are written as `constant` attributes, and modifiers in the grammar's order.** The pinned SysML v2 grammar spells `isReadOnly` as `constant`, so the migration now writes `constant attribute` instead of `readonly attribute`, which the parser and the pilot both reject as a syntax error. A property's direction, `derived`, `abstract` and `constant` are written in that order, so a read-only or abstract flow property (`in derived abstract constant attribute …`) parses in the pilot too. A read-only property of a data type or signal, whose attribute def cannot own a constant, is written without it and the report records the approximation.
