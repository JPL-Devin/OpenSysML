- **`FeaturesOf` no longer scans the parent scope to find a feature's owning type.** `findOwnerType` reads the owner the scope records and falls back to the scan only for a body re-owned by another declaration. Computing the effective features of a type is 13× faster; `-instantiate` and `%satisfy` over a large model are 6–7× faster than 0.4.3, and a gRPC `VerifyConstraint` request 13× faster than before the fix.
- **Action performances and constraint evaluation read a type's members once per runtime context.** Each nested action frame and each constraint check re-derived `MembersOf` of its type; the runtime now memoizes it for the context's life. Starting an action performance is 3× faster and evaluating one constraint over many objects 2.6× faster than before the fix. Evaluation also skips the resolver lookup for sub-action names when no action performance is on the stack.
- **Starting a state machine that no object exhibits allocates 47× less.** The search for the types that would exhibit it iterates each scope's members directly instead of building a deduplicated copy per scope; the start is 2.5× faster, though still proportional to model size (see the release comparison for the remaining work).
- **Control-node succession validation reads an action's visible members only when it must.** `ActionSuccessions` built the visible-member set of every action before looking at inherited successions; it is now built only when an inherited succession is named. Validating a 12 000-element model is 13% faster and allocates 18% less than before the fix.
